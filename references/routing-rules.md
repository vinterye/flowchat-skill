# Flowchat 连线规则（可执行口径）

这份文档是连线规则的**唯一文字来源**。原规则只存在于两张截图里
（`docs/flowchat-relative-position-routing-rules.png`、`docs/flowchat-1-to-many-connection-rules.png`），
agent 读不到，所以每次改动路由都要靠口头复述。这里把规则、阈值和已知边界都写死。

实现位置：`scripts/generate_flowchat.py`；门禁：`harness/flowchat_local_harness.py`；
回归用例：`tests/test_flowchat_routing_fixes.py`。

---

## 0. 常量

| 常量 | 值 | 含义 |
|---|---|---|
| `MIN_EDGE_LENGTH` | 90 | 连线总长下限，短于此直接判失败 |
| `MIN_ARROW_SEGMENT` | 75 | 箭头段（最后一段）下限 |
| `MIN_SEGMENT` | 8 | 单段下限，短于此会出现看不见的碎步 |
| `CENTRE_PENALTY` | 0.06 / px | 折点偏离中点的代价权重（小于一次弯折的 22，不会为居中而多折） |
| padding | 12 | 连线与其他节点的安全间距 |
| lane | 1/3 · 1/2 · 2/3 | 同一条边上的三个车道；普通 `side` 等价于车道 2 |

---

## 1. 节点中心与连接点

- 节点中心 = 矩形两条对角线的交点 = 几何中心。
- 四条边的中点是**边界连接点**，顺时针记为 1（上）、2（右）、3（下）、4（左）。
- 车道把每条边细分成 3 个可用位置：`1/3`、`1/2`、`2/3`。`1/2` 就是「边界中点」，
  也是普通 `side` 的落点 —— 所以一个矩形节点共有 **12 个**端口位置，不是 16 个。
- **例外**：菱形 / 六边形 / 八边形的四个顶点正好落在矩形边界中点上，所以矩形端口对它们有效。
- **例外**：圆形没有边界中点，端口落在外接矩形上，出线后再投影回圆周（`_snap_to_node_edge`）。
  首末两段仍然是轴对齐的。

## 2. 两个节点连接

- 连接点选**距离各自中心最近**的边界点。
- 尽量让两个节点的中心点居中对齐。
- 优先从边界线的中间位置出线。
- **折点必须落在两个节点之间的中点区域**（见 §5）。

## 3. 一对多（1→N）

- 1→2：两个目标组合后的中心与源中心对齐。
- 1→3 及更多：相邻目标**间距相等**，整组中心与源中心对齐。
- 先从源引出一条主线，再分成 N 条支线。
- **朝向必须由「源 → 目标组」的整体关系决定，全组统一**，不能逐边判定。
  逐边判定会让最外侧的目标在跨过 45° 时翻到另一个轴，共享主干随之消失。

  ```
  判据：比较源包围盒与目标组包围盒在两个轴上的净空 gap_x / gap_y
      gap 大的那个轴 = 组的朝向轴
      两者相等（差值 ≤ 1）时，用组质心相对源中心的主轴
  约束：只有当所有目标都真的在该方向上时才强制统一；
        源向相反象限扇出时没有单一主干，各边保留自己的方向。
  ```
- **四个正方向都要支持**：下、上、右、左。源在纵向组上按 x 居中，在横向组上按 y 居中。
- **离开端口的那一条边决定入线侧**：共用同一个出线端口的一组边，必须落到同一个入线侧
  （`left↔right`、`top↔bottom`），否则共享走廊会被拒，组会散开。

## 4. 多对一（N→1）

- 与扇出完全对称：先从各源分别引出，再在**目标组中心**汇合，共用一个汇入走廊。
- 汇入侧必须统一（所有边落到目标的同一条边），否则走廊不成立。
- **侧边入线阈值（§6）不适用于汇入组**：多个源汇入一个节点时，一律走目标面朝源那条边的中点。

## 5. 折点位置

- 折点优先放在**两个节点（或两个节点组）的中点**。
- 走廊轴 = `(源出线边坐标 + 目标入线边坐标) / 2`，再以 16px 步长**双向**外扩搜索避障
  （先试中点，再 ±16、±32 …）。
- 自动路由（A*）的候选坐标网格里必须包含中点，否则最优折点根本不可达；
  代价函数必须含居中项，否则曼哈顿长度恒等、折点位置只由入队顺序决定。
- 同一组连线的折点尽量落在同一条水平线或垂直线上。

## 6. 上下错位时的入线端口

纵向主导（`|dy| > |dx|`）时：

```
|dx| >= 目标宽 / 2 + MIN_ARROW_SEGMENT   →  入侧边（bottom → left / right，取更近一侧）
|dx| <  目标宽 / 2 + MIN_ARROW_SEGMENT   →  入顶部（bottom → top），折点取垂直中点
```

阈值 = 目标宽 ÷ 2（保证垂直线不穿过目标）+ 75（保证水平箭头段达标）。

| 目标宽 | 100 | 120 | 156 | 200 | 240 | 300 |
|---|---|---|---|---|---|---|
| 侧边阈值 | 125 | **135** | 153 | 175 | 195 | 225 |

- 区间 `目标宽/2 … 阈值` 之间**仍走顶部**：那里技术上可以从侧边进，但水平箭头段不足 75px，
  箭头会贴着目标边缘，视觉上没有「绕进来」的意思。
- 横向主导（`|dx| >= |dy|`）不受此阈值约束，一律水平进出。
- 左右距离过小（贴边）时：先从源底部垂直向下，再连到目标的顶部或侧边，折点仍取中点。

## 7. 整体视觉要求

- 连线只使用水平线和垂直线；禁止斜线、曲线、无意义折返。
- 同类关系使用同类路径：同方向、同层级的边用相同的出线/入线方式。
- 优先级（冲突时的决策顺序）：

  1. 不穿过节点
  2. 不与其他线交叉
  3. 使用最近边界点
  4. 保持中心对齐
  5. 减少折点和总长度
  6. 保持整体对称和视觉一致

## 8. 已知边界（不是 bug，但会撞到）

- **间距不足时保中点，允许箭头段变短。** 折点取中点后最后一段 = 间距 ÷ 2，
  间距 < 150px 时必然短于 75px。这类边会被打上 `data-arrow-relaxed="true"`，
  harness 对它只要求 `MIN_SEGMENT`（8px），其余边仍然卡 75px。
  报告里的 `arrow_relaxed_edges` 会列出全部被放行的边。
- **同一侧超过 3 条边**会挤在同一条车道上（车道只有 3 档）。生成器不再崩溃，
  但视觉会拥挤 —— 需要 4 条以上时，应该在数据层合并节点。
- **菱形 / 六边形 / 八边形无视 size 预设**，强制 150×106（`_normalize`）。
  受影响类型：decision、gate、rule、merge、checkpoint、milestone，以及所有六边形/八边形类型。
  同一行混放这些类型与常规节点时，中心必然错 9px。
- **横向净空接近 75px 时会出现 12px 的贴边折返**：源必须先沿法向走出 ≥8px，
  而末段又需要 ≥75px 的水平余量，两者在 75–83px 的净空下无法同时满足。
- **19 种边类型里只有 `return` 自带视觉差异**（虚线）。其余 18 种逐像素一致，
  7 个 arrow marker 共用同一份实现与同一个颜色 `#98a5bd`；差异只活在 DOM 的 `kind-*` 类名里。
  真正能改外观的只有三个开关：`kind-return`、`status=active|return`、`crossing:true`。

## 8.1 截图回归门禁

截图级回归必须同时满足以下结构，而不是只检查每条线“看起来能到”：

1. 1→N 扇出：同一 `fanout_group` 的源端点相同，先走一条主干，再在同一条分叉走廊上分支；源中心对齐目标组中心，目标间距一致。
2. N→1 汇合：同一 `fanin_group` 的目标端点与汇合前最后一段相同；目标中心对齐源组中心，源间距一致。
3. 1→1：在 `centered-flow` 下，源/目标中心在主轴上对齐，不为对齐制造额外回折。
4. Fork / Join：端点落在可见跑道边界中点；跑道背景高度必须覆盖端点，不得把线视觉上接到文字基线。
5. 主流程边状态为 `pending` / `completed` 时用实线；返工/回退边用 `return` 或显式 `crossing` 表达虚线。
6. `viewBox` 必须包含全部节点和渲染端点；fit-view 不能补救 SVG 自身的裁剪。

## 8.2 因果连线与共享上下文

当图声明 `dependency_contract: "causal-v1"` 时，连线必须有可回读的事实依据：

1. 节点用 `output_refs` 声明产生的结构化结果，用 `input_refs` 声明消费的结果。
2. 边用 `dependency.output_ref` 与 `dependency.input_ref` 连接源节点和目标节点的对应引用；两端引用不存在时生成失败。
3. `context_refs` 只表示共享运行上下文、用户请求、策略快照等只读信息，不生成视觉连线。
4. 禁止用 `type=context`、`kind=shared-context` 或类似边来替代结构化引用。
5. Agent 之间没有真实输入/输出依赖时保持断开；同一 Stage、同一 Run 或同一 Registry 归属不能单独产生边。

Harness 会逐边检查上述契约，并把 `dependency_edges_checked`、
`dependency_refs_checked`、`context_refs_checked` 写入报告。没有依赖证明的边是
`blocked`，不能用“看起来合理”代替事实。

## 9. 改动路由时的验证顺序

1. `python3 -m unittest discover -s flowchat/tests` —— 44 个用例，含 17 个针对本节规则的回归。
2. `python3 flowchat/scripts/generate_flowchat.py --graph <图> --output <html>` —— 必须 exit 0。
3. `python3 flowchat/harness/flowchat_local_harness.py <html> --browser-receipt <回执>` —— 静态检查 0 失败。
4. 浏览器回执与产物 sha256 绑定，换产物就要重跑真实浏览器会话；不要手工伪造回执内容。
